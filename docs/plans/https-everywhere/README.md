# HTTPS на всех стыках: план работ

Точка входа для любого исполнителя. Прочитай этот файл целиком, затем `design.md` и `codebase.md`, затем карточку своей задачи.

- Состояние: план согласован, реализация не начата.
- База: `main` на коммите `a6cc00d` (релиз 0.5.2), записано 2026-11-15.
- Если код разошёлся с тем, что здесь написано, верен код: обнови документ в том же PR.

## Что строим и зачем

Сегодня HTTPS-узел уже можно поставить в любую позицию цепочки, но вокруг него остались дыры. Закрываем пять:

1. **Настройки TLS на узле.** Сейчас у всех узлов один клиент TLS с корнями Mozilla. Нельзя задать свой CA, имя для проверки (SNI) и ключ узла. Узел, заданный IP-адресом, работает только при IP SAN в сертификате.
2. **Запрет деградации.** Протокол узла задаётся именем списка. Узел, по ошибке попавший в открытый список, уйдёт открытым текстом вместе с логином и паролем. Опечатка в ключе конфига молча выключает настройку.
3. **Ключ узла под контролем.** Ключ HTTPS-узла принимается только по двум независимым свидетельствам, сохраняется локально и проверяется при каждом рукопожатии. Так обнаруживается подмена на нашем канале и подмена узлом цепочки.
4. **Сверка через отдельные проверочные узлы.** Второй канал для сверки идёт через список прокси, которые не получают клиентский трафик.
5. **Входящий HTTPS.** Клиент может подключиться к самому resocks5 по TLS.

## Правила работы (обязательны)

Это правила владельца репозитория. Нарушать их нельзя, даже если так быстрее.

**Git и ветки.**

- Основной каталог всегда на `main`. Работа над задачей идёт в `worktrees/<slug>` на своей ветке: `git worktree add -b <slug> worktrees/<slug> main`. В slug включай метку задачи и дату, например `s1-tls-options-20261116`.
- Коммит и пуш — только по явной команде пользователя. Версии крейтов и зависимостей без команды не поднимаются.
- После слияния удаляются worktree, локальная и удалённая ветки.
- Команды `cargo` запускай из корня worktree, не из его родителя: из родителя cargo молча возьмёт основной каталог.

**Сборки и тесты.**

- Локально разрешены только `cargo check`, `cargo clippy`, `cargo fmt`. `cargo build`, `cargo test` и запуск приложения — только по явной просьбе пользователя.
- Тесты идут в GitHub CI. После пуша сразу ставь `gh pr checks <n> --watch -i 300` фоновой командой и жди уведомления. Опрашивать GitHub чаще раза в 300 с нельзя.
- Любое падение теста или нестабильный тест чинится в том же заходе до реальной причины. Не откладывается и не глушится.
- Перед пушем прогоняй `cargo clippy` по комбинациям features, которые задевает задача: `--no-default-features`, `--no-default-features --features pool`, `--no-default-features --features tls`, `--all-features`. Иначе `dead_code` и неразрешённые импорты всплывут только в CI.

**Структура кода (проверяет CI).**

- Не больше 1000 строк в файле Rust и не больше 7 записей в каталоге. Заполненные каталоги перечислены в `codebase.md`.
- Доктесты запрещены: примеры в документации — в блоках ` ```text `.
- Комментарии в коде короткие.

**Безопасность.**

- Логины, пароли и закрытые ключи не печатаются в консоль, лог, тесты и документы.
- Работа только внутри каталога репозитория. Файлы настроек пользователя вне репозитория не трогаются.
- Процессы завершаются только по своему PID, никогда по имени образа.

**Под-агенты.** Запускаются только по явной просьбе пользователя, каждый в своём worktree. Правило про сборки и тесты включается в их задание.

## Готовность задачи

Задача готова, когда выполнено всё:

1. Сделано то, что перечислено в карточке, и ничего сверх неё.
2. Написаны тесты из раздела «Приёмка» карточки.
3. `cargo fmt --check` и `cargo clippy -D warnings` чисты во всех задетых комбинациях features.
4. CI на PR зелёный целиком, включая `structure`, `doc`, `net-features`, `feature-unification`, `deny`.
5. Обновлены документы, которые задача делает неверными, включая этот каталог.
6. PR слит, worktree и ветки удалены.

## Что проверено и что нет

**Проверено чтением исходников** (`rustls 0.23.45`, `rustls-webpki 0.103.15`, `rcgen 0.13.2`, `ktav 0.8.0` в локальном реестре; в `Cargo.lock` версии на одну правку новее):

- SPKI листового сертификата отдаёт `ParsedCertificate::subject_public_key_info()`: новый разборщик X.509 не нужен;
- пользовательский верификатор и штатные функции проверки подписи рукопожатия доступны;
- `rcgen` имеет feature `ring` без `aws-lc-rs`, лицензия `MIT OR Apache-2.0`;
- мост `ktav` к serde идёт через обычные `deserialize_struct` и `deserialize_map`.

**Не проверено сборкой и тестом** — это делает S0:

- всё перечисленное выше на версиях из `Cargo.lock`;
- что `deny_unknown_fields` действительно даёт ошибку через `ktav` и что в ней есть имя ключа и номер строки;
- что зависимости `rcgen` проходят `cargo deny` и MSRV 1.88; сборка под `musl` проверяется в S10;
- разбирает ли `ktav` ключ карты с двоеточием (`host:port`) — проверяется в S12.

**Не проверено вовсе:**

- как ведут себя обработчики восстановления туннеля при закрытии TLS-потока (`close_notify` вместо полузакрытия TCP) — проверяется тестом в S6;
- есть ли в приложении места, различающие `AnyUpstream::Tls` и `AnyUpstream::Gate`, — проверяется в S4, часть 3;
- все ли вызывающие `pick_order` и `pick_iter` переносят пустой результат — проверяется в S4, часть 1.

## Глоссарий

- **Узел** — один прокси из списка (`ProxyConfig`).
- **Выход** — узел без метки `*`, последний в цепочке перед целью.
- **Мост (gate)** — узел с меткой `*`; число звёздочек — ранг, больший ранг набирается раньше.
- **Цепочка** — мосты по убыванию ранга и выход.
- **Рабочий путь узла** — цепочка, которой узел набирается при обслуживании клиента.
- **Проверочный узел** — узел из объекта `verify`; клиентский трафик через него не идёт.
- **Ключ узла** — SHA-256 от SPKI листового сертификата узла, запись `sha256/<base64>`.
- **Пин** — сохранённый ключ узла и сведения о том, как он принят.
- **Сверенный узел** — HTTPS-узел с действующим пином.
- **Канал** — цепочка узлов, по которой мы доходим до сверяемого узла и делаем с ним TLS-рукопожатие.
- **Множество вмешательства** — узлы канала, способные подменить это рукопожатие.
- **Свидетельство** — наблюдение ключа узла: по каналу либо через проверку цепочки сертификата.
- **Пауза (hold)** — исключение узла из выбора ротатором, не связанное с карантином.
- **Карантин** — существующий механизм: узел после жёстких отказов исключается на растущий срок и возвращается по пробе.
