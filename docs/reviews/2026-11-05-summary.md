## 1. Приоритетные дефекты

Все V01–V18 ниже имеют статус VERIFIED_STATIC и высокую уверенность в механизме. Severity откалибрована независимым verifier, не перенесена автоматически из тематических отчётов.

### V01 — High: полностью исключённый exit оставляет экспоненциальный обход

Источники: DT-B01.

Места: `crates/resocks5-net/src/session/chain/mod.rs:223–245,273–289,360–364`; `crates/resocks5/src/server/connect/establish_connection/dial.rs:191–199`.

План содержит d gate-слоёв по два кандидата и один exit E. Первый next выдаёт цепочку и advance-ит позицию. После target failure E становится dead. Каждый следующий проход видит dead E последнего слоя, jump_subtree переполняет singleton exit и переносит odometer в предыдущие gates. Нет проверки, что в exit-слое вообще больше не осталось живых кандидатов.

Малый аналитический пример: `[A0,A1] × [B0,B1] × [E]`. После первой `A0,B0,E` и mark_dead(E) обход посещает `A0,B1,E`, `A1,B0,E`, `A1,B1,E`, хотя все невозможны. Для d двоичных уровней после первой попытки остаётся до **2^d−1 бесполезных комбинаций**, каждая дополнительно проверяет слои и identity hashes. При d=20 это 1048575 комбинаций — не измерение времени.

`next()` синхронный, без await; app увеличивает attempts лишь после его возврата. Поэтому сетевой cap не ограничивает эту CPU-работу, fallback задерживается, async timeout не может принудительно прервать полл.

**Направление решения:** состояние живых candidates по слою; полностью исчерпанный слой немедленно завершает план. Для частично живых сохранить порядок и pruning.

**Тест-кандидат:** небольшой план, первый pick, mark exit dead, затем None и deterministic transition-count bound по сумме размеров слоёв, не по произведению. Positive control: один из двух exits жив. Mutation: убрать early exhaustion termination. Не создавать гигантский Cartesian product как нагрузочный oracle.

### V02 — Medium: health writer нарушает lifecycle сохранения и границу shutdown

Источники: ASYNC-01, DROP-01/02/03.

Места: `crates/resocks5/src/server/health/mod.rs:258–265,280–303`; `crates/resocks5/src/server/bootstrap/startup.rs:525–534`; `crates/resocks5/src/config/users/users_file/mod.rs:99–153`; `crates/resocks5/src/server/bootstrap/runtime.rs:51–57`.

Три связанные, но отдельные ошибки:

1. Serialization/write/sync/commit выполняются синхронно внутри async saver и блокируют runtime worker на storage.
2. Shutdown делает abort без await и немедленный save_now. Уже выполняющийся sync участок saver продолжает работу: старый A владеет общим temp, финальный B получает AlreadyExists, A публикует устаревшее состояние.
3. Crash после создания фиксированного temp оставляет orphan. `create_new` сохраняет recovery-файл; health recovery policy отсутствует, последующие saves могут постоянно отказывать и после рестарта.

Пятисекундный runtime teardown начинается после возврата block_on; inline final save до него не ограничен. Это не ошибка самого shutdown_timeout, а его области действия.

**Направление:** один persistence owner, final-snapshot/stop/ack protocol, отдельная health temp/recovery policy и bounded-exit/loss policy. Timeout вокруг spawn_blocking не отменяет начатый syscall. Users recovery-temp нельзя автоматически удалять по новой health-политике.

**Тесты:** writer barrier после temp, смена health, shutdown, отсутствие второго writer и final B; blocked writer с бюджетом и последующим release собственного worker; orphan temp с прежним/отсутствующим target. Mutations: abort+save_now без serialization, inline sync save, fixed temp без recovery.

### V03 — Medium: hedge допускает одновременные CONNECT уже запущенных кандидатов

Источники: CON-01, ASYNC-04, CONF-01.

Места: `crates/resocks5-net/src/connect/proxy_connect/hedged.rs:145–165,277–305`; SDK README397–405.

A TCP pending → hedge запускает B → A начинает CONNECT и ждёт → B получает socket до winner, видит won=false и тоже вызывает handshake. handshaking запрещает новые launches, но не admission уже launched attempts. Winner публикуется coordinator-ом, а не самим успешным attempt.

**Влияние:** два target connections/CONNECT вопреки обещанию. Повторная отправка application payload не доказана.

**Направление:** эксклюзивный RAII переход TCP-ready→handshake, winner recheck после admission и публикация success до следующего admission.

**Тест:** управляемые TCP completions, первый CONNECT заблокирован, второй не появляется до отказа первого; при success второго CONNECT нет. Mutation: admission заменить счётчиком. Existing slow-handshake test проверяет ещё не launched второй candidate, не эту гонку.

### V04 — Medium: queued sticky fallback позволяет превысить общий route budget

Источники: CONF-08.

Место: `crates/resocks5/src/server/connect/establish_connection/dial.rs:75–88,188–199,278–320`.

Ordinary cached routes queued без расхода attempts; chain loop резервирует один fallback slot, позднее ограничение влияет только на добавление новых candidates, не на уже queued sticky slice.

**Достижимая история при gates/max=3:** G отказывает на TCP, fallback закрепляет ordinary E6. В следующем запросе G снова отказывает, cached E6 TCP медленный, E4 выигрывает hedge и закрепляется; late E6 получает Lost, старый E6 cache сохраняется. Два ordinary caches существуют в независимых rotators при настроенных gates. Затем G доступен: новый запрос queued-ит оба caches, делает две chain attempts с target failures и передаёт оба cached routes целиком connect_hedged. Если оба запускаются — 4 attempts при cap3. Двух ранних G failures недостаточно для default threshold3 quarantine, поэтому история не требует невозможного health состояния.

**Направление:** единый расходуемый launch budget, clamp всего fallback slice остатком, включая cached routes.

**Тест:** создать caches обычной историей fallback/late Lost, затем gated failures, wire launch count≤3. Mutation: не учитывать queued caches/не clamp slice.

### V05 — Medium: cached chain обходит quarantine gates

Источники: DT-B03, CONF-02.

Места: `crates/resocks5-net/src/session/rotator/mod.rs:430–435`; `session/chain/mod.rs:49–85`; `crates/resocks5/src/server/connect/establish_connection/dial.rs:75–126`.

Exit get_linked проверяет E, resolve identity-only восстанавливает G_bad→E без health gates. При healthy G_good cached request всё равно dial-ит quarantined G_bad.

**Направление:** application cached-route admission проверяет каждый hop. Identity-only resolve не менять: его semantics явно закреплены SDK test.

**Тест:** cached bad+healthy alternative, bad dial count0, recovery positive. Mutation убрать per-hop eligibility.

### V06 — Medium: duplicate identity quarantine обновляет только последний alias

Источники: DT-B02.

Места: `crates/resocks5-net/src/session/rotator/mod.rs:375–393,465–495`; `session/rating/mod.rs:248–264`; `session/rotator/tests.rs:53–59`.

[A,A,B] создаёт отдельные state cells, index_of(A) всегда последний slot. После quarantine последний A исключён, первый остаётся healthy и selectable, его событие снова обновляет последний slot. Здоровый B исключает объяснение all-down fallback.

**Направление:** явная duplicates policy — dedup либо multiplicity weight с общей state. Не начислять несколько failures за один identity result.

**Тест:** threshold1, failure(A), ни одного A в order при healthy B; recovery по policy. Mutation separate cells/last lookup.

### V07 — Medium: capacity/prefix failure ошибочно штрафует внутренний gate

Источники: CON-03, CONF-04.

Места: `crates/resocks5/src/server/connect/establish_connection/probes.rs:76–109`; `crates/resocks5-net/src/connect/dial/chain_pool.rs:68–88`.

.is_ok теряет ChainError/stage: occupied outer permit, failure prefix либо недостижение tested node одинаково становятся hard failure внутреннего gate и удваивают quarantine.

**Направление:** typed/staged outcome success/down-tested/inconclusive; capacity и prefix errors не штрафуют tested node.

**Тест:** occupied prefix, no tested-node health change; release normal probe; prefix refusal и настоящий tested-node refusal отдельно. Mutation bool outcome.

### V08 — Medium: whole-chain probe может пережить lease, stale settlement не различается

Источники: CON-04, ASYNC-03.

Места: `crates/resocks5/src/server/bootstrap/startup.rs:337–352`; `server/connect/establish_connection/probes.rs:48–109`; `crates/resocks5-net/src/connect/dial/chain.rs:365–373`; `session/rating/quarantine.rs:232–247`.

Lease connect+один handshake+5s defaults25s; три prefix handshakes по9s уже27s без TCP. Выдаётся повторный probe, outcomes без generation; late success старого очищает новое состояние.

**Направление:** whole-probe absolute deadline согласован с lease, generation/token settlement. Только увеличить lease недостаточно для late scheduling.

**Тест:** контролируемые hops/time, lease boundary, stale result и owner cancel. Mutations one-hop lease/no generation check.

### V09 — Medium: health restore direct-probes внутренние gates

Источники: CON-06, ASYNC-02, CONF-03.

Места: `crates/resocks5/src/server/bootstrap/startup.rs:158–166,465–477`; `server/health/mod.rs:231–248`; `server/connect/establish_connection/route.rs:49–57`; `crates/resocks5-net/src/session/rotator/probe.rs:42–47`.

All rotators включают internal levels, restore вызывает topology-blind direct probes. B reachable через A, но direct unreachable, falsely quarantined; direct success тоже не проверяет prefix.

**Направление:** restore отдельно, topology-aware dispatch; прямой путь только outermost/exits.

**Тест:** direct B запрещён, A→B работает; direct count0/outer CONNECT/recovery. Mutation обычные probes по всем rotators. IP сервера видит диагностируемый endpoint; более широкая утечка target-сайту этим не установлена.

### V10 — Medium: health roundtrip сливает независимые routing groups

Источники: CONF-05; DT-H01 частично.

Места: `crates/resocks5/src/server/health/mod.rs:96–108,136–164`; `server/bootstrap/startup.rs:262–289,371–388`; `docs/REFERENCE.md:411–413`.

Snapshot emits все groups, restore key=(label,gate_level) без group. Один endpoint в v6/v4 rotators с opposite health: last alive стирает quarantine обоих, last quarantined применяется обоим. Даже одинаковых credentials достаточно; runtime groups независимы.

**Направление:** stable group discriminator и явная old ambiguous record policy. Password не писать.

**Тест:** runtime snapshot/save/load/fresh restore opposite states и trips, оба declaration order. Mutation удалить group. KTAV struct roundtrip это не проверяет. Password-distinct aliases — отдельная password-free ambiguity policy, не повод писать пароль/hash.

## 5. Отклонённые/условные security и API claims

### Publish token/cache

DF-02, `.github/workflows/release.yml:192–230`: secret-free dry-run перед token-bearing publish, mode-conditional API token/OIDC, publish без no-verify, job с rust-cache. Потенциальная граница build-time execution при secret-bearing upload есть.
